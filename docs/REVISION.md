# Ревизия сервисов Домиан — проверка отчёта ChatGPT

Дата проверки: 27 сентября 2026. Репозитории скачаны и проверены по коду. Секреты и персональные данные в этом документе не воспроизводятся: указаны только факты и счётчики.

## Итог

С отчётом ChatGPT **согласен по сути**: все факты, которые я мог проверить, подтвердились. Вывод верный: нужен новый приватный сервис с серверной авторизацией, а старые репозитории — доноры. Ниже — что подтвердилось, что ChatGPT упустил и где я предлагаю иначе.

## Что ChatGPT упустил

1. **FrDomianReview, Royalty и Plans тоже публичные.** В FrDomianReview лежит `yandex-disk-index.json` (1,6 МБ): полная структура франшизной папки — 2 241 имя файла, из них 59 договоров. Публичных ссылок на диск нет, но имена файлов сами по себе — внутренняя информация. В Royalty есть 20-значный счёт и ИНН (вероятно, реквизиты франчайзера — критичность ниже, но проверить).
2. **Git-история.** В FrDomian 7 коммитов, в officeip — 6. Если данные закрыть только в последней версии, они останутся в истории. Кроме того, раз репозитории были публичными, их копии уже могли скачать. Значит: сначала сменить пароли, закрыть доступ и перевести репозитории в private, затем чистить историю (`git filter-repo`). ChatGPT упоминает это одной строкой — на деле это главный пункт.
3. **152-ФЗ.** В officeip — персональные данные ИП (ФИО, ИНН, счета, телефоны). Новый сервис с такими данными должен размещаться на серверах в РФ (Yandex Cloud, Selectel, Timeweb и т. п.). Supabase, Vercel и Firebase для боевых данных не подходят. От этого зависит выбор хостинга, поэтому решать нужно до запуска.
4. **Банковские реквизиты — не «справочник».** Их видят все, у кого есть ссылка. В новом сервисе реквизиты отделены от карточки офиса: их видит только собственник/руководитель этого офиса и франшизный отдел, каждый просмотр пишется в журнал.

## Где я предлагаю иначе

| ChatGPT | Моё предложение | Почему |
|---|---|---|
| React + TypeScript + отдельный API + PostgreSQL | **Node 24 без внешних зависимостей**: `node:http`, `node:sqlite`, `node:crypto`; фронтенд — ES-модули без сборки | Проект ведёт один человек с ИИ. Ноль `npm install` — ноль уязвимых пакетов в цепочке поставки, запуск офлайн одной командой, тот же стиль, что в Dom2 (чистый JS + `node --test`). PostgreSQL понадобится при сотнях пользователей; для ~80 офисов SQLite хватает с большим запасом, схема переносима |
| Калькуляторы переносить «почти напрямую» | Переносить **с проверкой правил**. Пример: пакет мотивации в Dom2 зависит от прошлого пакета (повышение / снижение на одну ступень / без изменений), а не просто от уровня полугодия | Простой перенос формулы уже дал бы ошибку — см. `shared/calculators.js`, `performanceDecision` |
| Справочник офисов = officeip в БД | Разделить на **«Сеть»** (адрес, рабочий телефон — видят все) и **«Мой офис»** (реквизиты, собственник — только свои) | Сейчас каждый собственник видит счета всех остальных |

## Срочно (P0) — до любой разработки

1. Перевести в **private**: officeip, FrDomian, Instrukciya, Dom2, FrDomianReview, Royalty (и остальные по списку ниже).
2. Сменить пароль FrDomian, код доступа Dom2 и токен FrDomian — считать их скомпрометированными.
3. Если нужно, чтобы страницы продолжали работать до нового сервиса: GitHub Pages на приватном репозитории требует платного тарифа, и страница всё равно остаётся публичной. Честный вариант — временно отключить Pages у officeip и FrDomian.
4. После смены секретов — чистка истории (`git filter-repo`) и повторная проверка.
5. Проверить **остальные** репозитории. На 27.09.2026 в аккаунте **34 репозитория, все публичные, ни одного приватного**. Эта ревизия покрыла 8 из них. По названиям в первую очередь стоит проверить: `Domianfin`, `wikidomian`, `Office`, `dosie`, `CatalogDomian`, `DomianKvartal`, `DomianNov`, `DomianShakhty`.

Публичными по смыслу могут остаться только лендинг франшизы (KP) и то, что предназначено для клиентов.
